# 三层案例验收台

启动 `pnpm dev --host 127.0.0.1` 后打开首页。案例文件在 `public/cases/`，与 Python 处理层使用相同的 entities/scene/sources 格式；页面并不调用模型或运行 Python。正常案例通过 Python 合同校验，两个故障案例按预期被合同校验拒绝。

## 建议测试顺序

1. **渡口 · 正常交接**：观察 5 个对象，切换全景、人尺度、俯视；拖动旋转，点击桥或货物查看尺寸与来源。导出 scene.json 确认有 5 个 placements。
2. **资料缺了一条**：木桥引用 missing-record。采集器显示待补资料，侧栏指出缺失 ID。查看处理层时仍能看到演示尺寸依据。
3. **模型加载失败**：木桥引用不存在的 GLB。出现橙色占位，另外 4 个对象正常。重新加载仍显示明确失败。此案例的网络失败是故意构造的。
4. **真实 Tripo 候选**：默认读取 `public/cases/tripo/assets/tripo-candidate.glb`。该生成模型不进 Git；在本机有文件时可直接显示，在其他机器上用“选择本地 GLB”。文件通过浏览器 Blob URL 读取，不上传，不创建付费任务。

每个案例有三项手动验收勾选。切换案例或重新加载会清空本轮勾选。它们记录用户本轮观察，不代表自动化测试通过。

点击顶部三层卡片，查看对应层的输入、交付与缺口；可展开当前层交接数据。前端支持预览、来源检查、模型降级和 JSON 导出，暂未实现第一人称行走、碰撞、两点测距。

所有渡口资料、几何与尺寸均为虚构测试设定。真实 GLB 仅通过包围盒统一缩放到最长边 3 米，并居中接地；这不是历史尺度校准，也没有自动批准候选。
