# 自动审查核验结论（REV4）

PR #10 的自动审查使用了截断的 diff，丢弃约 218 万字符，未覆盖运行时代码。人工回到基线、当前提交和干净解包结果核对，未发现当前成品的新增阻断问题。

凭据意见的前提不成立：基线已经忽略 `.processing-data/`，该目录没有跟踪文件；逐文件扫描当前 Git 提交没有凭据命中。正常 `yuezhi:prepare/check/build` 仅读正式资产并校验 SHA，不运行付费生成配方；同机新目录用无密钥的正式快照通过 227 项测试、构建和桌面走读。

旧人物生成脚本仍保留本机文件读取方式，旧归一化脚本确有非方形纹理缩放和 raw 前置验证不足。这些是可选作者工具的后续改进，不是正常接力运行入口。旧三项任务缺失原始 provider 收据与 raw，不能把配方脚本反称为已发送请求证据；复用这些脚本前应单独补验证，优先采用环境变量凭据。此次不改已绑定 hash 的历史证据，不重复生成收费资产。

`-text` 保护成品快照原字节，未设置 `-diff`，业务源码在保护树之外。`book.json` 由 canonical `bookScenes` 自动生成；并非手工维护两份。匈奴手臂校准后重算法线是有意派生，UV 保留，输出有独立 hash 和实际画面验证。最终 ZIP 和 Git 均排除 `.blend`、运行缓存及用户要求暂留的四个探索原型文件。

可选作者工具的下载校验、报错、性能与中断恢复改进已记录在 `validation/github-review-resolution.json`。现有模型的正常预览不运行这些工具。未代签史料、视觉或公开使用权利，仍为 `needs_review`。

复盘：自动审查对截断 diff 的判断应回完整文件确认；成品校验与作者工具重生成是不同证据边界。记录归项目 `failure_record` / `no_persist`，不改变全局 memory、skill 或安全规则。
