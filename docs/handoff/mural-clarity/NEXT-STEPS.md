## 第一优先级：先交可读的完整故事稿

用户最新方向是“故事优先，图片、3D给故事让路”。先不动资产、不重新收费生成Tripo，不继续润色“左上/左下/山石遮挡”的读画主线。先写一份从任务、阻碍、行动、结果到影响的完整中文故事，陌生读者不看图也应能理解。用清楚的人物、时间与因果说明，避免为了互动虚构史实和随意分支。

建议按下列八章重组；这是下一轮的候选时间线，不是当前代码已实现的内容：

1. **奉命出发**：汉武帝为什么需要月氏这个盟友，张骞接受什么任务，为什么必须向西。交代共同敌人匈奴与月氏西迁背景。
2. **被匈奴扣留**：西行途中为何被拦、扣留如何打断任务。史书记载十余年及“持汉节不失”；不编造牢房刑罚或丢失汉节。
3. **逃出后继续西行**：为什么不直接回汉，如何经大宛、康居抵达大月氏。这里穿插行路3D，让观者理解仍在执行使命，而非解释壁画布局。
4. **求盟没有成功**：张骞提出联合对抗匈奴，月氏已经安居、担心汉朝遥远，故不愿重启战争。画面是正式接见示意，不能叫成功会盟。
5. **在大夏获得新见闻**：外交受挫却了解到城邑、市场和远方贸易；蜀布、邛竹杖、身毒线索意味着什么。解释名词后说清它们为何值得带回汉朝。
6. **归途再受阻，终于返汉**：归路再次落入匈奴，后来脱身，十三年后与堂邑父等返回。按《史记》逐项核对人数、年数与称谓，不凭印象填日期。
7. **失败任务带来的成果**：求盟未成，却带回西域知识，为之后外交和交通往来提供基础。区分首次与后续出使，不把后来成果全归入一次旅程。
8. **后人怎样记住这次远行**：故事讲完后，再回到初唐第323窟壁画。金人、僧人和佛塔是后世佛教叙事；说明它与汉代史书记载的差别，不把见僧问佛、带佛教入华当首次出使事实。

每章先有“发生了什么、为什么、结果怎样”，再用一两句图片/3D讲解补充。用户之前要求动画与文字对应、动作完成再讲述；新编排若需要改变播放顺序，应明确呈现新方案供用户审阅，不擅自取消现有约束。先给用户看完整讲稿，再录音与改场景，避免下一版又因方向错而全部重录。

`History3D/`包含完整可审阅的项目源码、锁文件、测试、既有yuezhi页面、当前11份3D资产、当前及保留的旧旁白成品、壁画图片、来源/许可、作者脚本。`验收证据/`保存本次r5记录和它们实际引用的图像/播放trace；`交付工具/`包含冻结、封包和新目录核验工具。根部有 `请先阅读.md`、本文件和ZIP-MANIFEST逐文件校验清单。

“全部内容”指接力运行和继续开发需要的代码、成品、说明及证据。私人提取音色/参考录音、凭据、GPT-SoVITS私人模型、WAV作者缓存、语音权重、venv、node_modules、dist与.git不放包。普通查看不用provider密钥；依赖由锁文件重建。不要把私人音声加入GitHub或后续ZIP。

新电脑需 Node.js 22.12+ 和Python 3；在 `History3D/`执行：

```powershell
npm ci
npm run check
npm run build
npm run preview -- --host 127.0.0.1 --port 5194 --strictPort
```

电脑浏览器打开 `http://127.0.0.1:5194/mural.html`，旧 `/yuezhi.html`也保留。编辑可用 `npm run dev -- --host 127.0.0.1 --port 5194 --strictPort`。

重录需要Python独立环境、Kokoro锁文件、官方固定版本公开模型、FFmpeg/FFprobe；完整配方和许可见 `docs/handoff/mural-clarity/narration-v4.md`。模型体积大，包中只放成品和复现指针；安装外部工具前核对来源。保留zm_010，不能偷偷退回私人克隆音色。
