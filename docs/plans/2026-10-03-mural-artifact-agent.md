# 壁画与文物故事 Agent Implementation Plan

> **执行：** Codex 使用本项目已有工作区分阶段实施，先核对证据，再审核产物；保持主代理加两名子代理上限。

**Goal:** 用户在本地网页选择壁画或文物，提供图片与来源，填写模型和 Tripo API，得到以故事为主、真实 3D 辅助、可以检查细节的桌面讲解网页。

**Architecture:** 共用 A 采集、B 审核整合、C 网页、D 实际验证，按题材选择规划规则和展示方式。壁画保留人物事件与原图定位；文物以主器物为中心讲用途、制作、纹饰和历史，主器物由原照片图生 3D。生成结果仍须人检查；照片没有覆盖的背面、内部、原色和缺损补全不能当成已知事实。

**Tech Stack:** TypeScript、Node HTTP、OpenAI-compatible vision、Tripo v3、Three.js、自包含 GLB、Vitest。旁白继续使用用户认可的本机公开参考推理，不训练模型。

---

## 当前证据与边界

- 张骞字幕 v12：24 轨、947 字时点，原音轨字节与正文不变；真实媒体时钟驱动字幕，暂停/倍速/前后拖动有浏览器观察。
- 最新字幕范围完整 check：355 pass/4 skip；独立目录 Vite build exit 0。旧 npm build 在生成目录 rename 遭 EPERM，不能写为通过。
- 通用 Agent 已有严格合同、故事审核、计划指纹、预算、密钥仅 RAM、未知提交不重发、真实 UV/PBR GLB 检查及导出网页。
- 通用 viewer 目前只做静态预览与逐句阅读；完整旁白、动作、录屏和 ZIP 仍需完成。离线 provider fixture 不能证明真实 API 效果。
- 源码、原始媒体、任务回执和依赖必须放入交接；私人音声、私人权重、API Key 不进入成果。

## Task 1：文物输入与合同

**Files:** `agent/contracts.ts`、`agent/server.ts`、`tests/mural-agent-server.test.ts`、独立模式合同测试。

1. 写两模式输入测试：缺省为旧壁画模式、文物模式可解析；无效模式拒绝，凭据不得进入持久状态。
2. 跑失败测试，冻结 schema 后实现 `subjectType`、可选文物信息、照片细节定位与主资产身份。
3. 文物主资产必须为照片驱动的器物；辅助环境与人物仍可按来源生成。所有细节讲解都保留来源与事实/推断标签。
4. 以 `npm run test -- tests/mural-agent-server.test.ts` 和独立合同测试验收，并检查旧运行恢复和计划 hash。

## Task 2：真实图生资产链路

**Files:** `agent/server.ts`、必要 provider 辅助模块、后端失败测试。

1. 根据 Tripo 官方 v3 文档核对上传和 image-to-model，不猜接口。
2. 原照片 SHA、上传回执、生成 intent、task receipt、GLB SHA 构成一条可回查链；故事与预算确认前不上传生成。
3. 上传/生成未知状态、重启、并发、失败响应、泄漏字段分别验证，未知付费任务不得自动重新提交。
4. 复用实际自包含 GLB 校验。结构通过不等于器形、纹饰和修复解释正确。

## Task 3：本地配置与文物细节展示

**Files:** `agent/web/index.html`、`app.js`、`style.css`、`viewer.html`、`viewer.js`、`viewer.css`。

1. 题材选择改真实提交字段；按题材更换输入说明和故事提示，保留输入内容与密钥 RAM 边界。
2. 文物模式原照片与实际主资产配对；细节标注定位在原照片上，局部可放大，3D 可旋转、缩放和复位。
3. 模型没有依据的 3D 内部位置不能被标成精确器物细节；先用实际照片验证纹饰，再用生成 3D 解释体积和用途。
4. 真实浏览器检查切换、恢复、错误、故事审核、预览和细节查看。只有桌面布局。

## Task 4：旁白与质量规则

**Files:** 新版本项目质量规则、`docs/agent/`、旁白生成与导出模块、viewer 播放模块。

1. 保留 r10 规则冻结证据，单独扩展文物规则：器物身份、真实照片、尺寸依据、残损与补全、纹饰证据、故事与细节绑定。
2. 接入用户认可的本地旁白；每句正文、音轨 SHA 与字幕时间戳绑定，长静音和缺句不能因 HTTP 200 而通过。
3. 媒体时钟驱动字幕；观察/动作先完成，再开始对应讲解。暂停、倍速、拖动和音频重开要实际验证。
4. 文物不强制人物走路；有历史人物场景时才用已验证动作。不要用僵硬平移代替走路。

## Task 5：真实验收与交接

**Files:** 版本化验证日志、录屏、视觉资产看板、项目全量源码 ZIP、交接说明。

1. 完整 check 与 build；故障日志范围写清，旧版本测试不认证新改动。
2. 实际壁画和文物各跑一例；若只有 fixture，明确待真实 API 验证，不把假 task 当真资产回执。
3. 看故事因果、镜头空白、器物细节、文字位置、声音和字幕，保存可复核截图与完整自然播放证据。
4. 打包源码、实际素材、规则、生成脚本、来源与启动说明；在新目录解压并核验文件/启动。不要仅交 Markdown。
5. 未完成项逐项列出；不自动发布、合并或上传 GitHub。用户复核效果后继续交付。

## 复盘与持久化

本计划属于项目产物与 `no_persist`；字幕故障与接口失败记录属于项目 `failure_record` 候选，来源为实际命令和浏览器观察。模型路由选择与验证写追加日志。此次不改全局 memory、active skill、安全规则或用户批准权限。
